# MY APP MAKER 기획서 검토

검토 대상: 「MY APP MAKER 어린이 앱 만들기 프로젝트 — 학생용 앱 기획·저장 기능 및 수업 문서 기획서」
운영 조건: 학생 약 20명 · **40분 × 4차시** · 결과물을 메타버스 공간에 입점

---

## 한눈에 보기

| 구분 | 판단 |
|---|---|
| 교육 방향 | ✅ 매우 좋음 — "AI가 대신 만들지 않고, 학생이 목표·규칙·캐릭터를 정한다"는 원칙이 분명함 |
| 주제·미리보기 | ✅ 20개 주제 + 미리보기로 "무엇을 만들지 모르겠어요"를 줄임 → (반영) 학생이 원하는 것을 말하면 추천하는 방식으로 바꿈 |
| 앱 = 활동지 일치 | ✅ 입력 항목과 활동지 순서를 맞춘 설계가 좋음 |
| 프롬프트 설계 | ✅ 앱/이미지 분리, 단일 HTML, 저작권·글자 금지 등 구체적 |
| **차시** | ⚠️ 기획서는 **10차시**, 실제 운영은 **4차시** → 분량을 절반 이하로 줄여야 함 |
| **교사 페이지** | ⚠️ 기획서는 "이번 범위 제외"지만, 4차시 안에 입점까지 하려면 **제출 취합·승인 기능이 반드시 필요** |
| **메타버스 입점 경로** | ⚠️ "개별 URL로 게시 → 부스 연결"이 4차시 안에 현실적이지 않음 |
| **저장·취합** | ⚠️ 브라우저 저장만으로는 20대 기기에서 모을 수 없고, **공용 태블릿이면 서로 덮어쓸 위험** |
| **AI 도구 계정** | ⚠️ 학생 연령과 서비스 가입 조건 확인이 빠져 있음 |
| 학생 앱 실행 안전 | ⚠️ AI가 만든 코드를 그대로 실행하는 데 대한 격리 방안이 없음 |

## 1. 잘된 점

1. **학생이 기획자**: 프롬프트가 주제명만 바꾸는 방식이 아니라 목표·규칙·캐릭터·추가 아이디어를 모두 담도록 요구해, 학생 생각이 결과물에 그대로 드러납니다.
2. **미리보기 후 선택**: 바로 선택하지 않고 목표·진행 3단계·예상 화면을 먼저 보게 한 점이 좋습니다. "구성 예시"임을 표시하라는 지침도 적절합니다.
3. **저장 요구사항이 구체적**: 자동 저장, 상태 표시(저장 중/완료/실패), 초기화 확인, JSON 백업까지 학생이 실제로 겪는 사고를 잘 짚었습니다.
4. **이미지 프롬프트 지침**: 캐릭터 일관성, 글자·로고 금지, 투명 배경과 16:9 배경 구분, 유명 캐릭터 모방 금지 — 그대로 반영했습니다.
5. **JSON 구조를 일관되게** 두어 나중에 교사 페이지와 연동하겠다는 판단이 옳습니다(이번에 실제로 그 구조로 연동했습니다).

## 2. 보완이 필요한 점

### 2-1. 10차시 → 4차시 (가장 큰 문제)

기획서 10장의 운영안은 기획 4차시 + 제작 2차시 + 테스트·입점·발표 4차시입니다. 160분 안에 끝내려면 **덜 중요한 것을 빼는 것**이 핵심입니다.

| 줄인 것 | 방법 |
|---|---|
| 15개 항목 손글씨 작성 | ★ 꼭 쓰기 **7개**(1 기본 정보, 2 소개, 4 목표, 5 규칙, 6 캐릭터, 7 기능, 12 특별 기능)만 필수. 나머지는 선택 |
| 기능·요소·화면·디자인 서술 | **칩(버튼)으로 고르기** — 8·9·11·14번은 몇 번 누르면 끝 |
| 이미지 생성(5~6차시) | **선택 과제**로. 앱 제작 프롬프트가 이모지·도형으로 그리게 하고, 그림 넣을 자리(`IMAGES`)만 만들어 둠 |
| 웹 게시·URL 만들기(8차시) | 학생은 **코드를 붙여 넣고 「보내기」**만. 게시는 앱 월드가 대신 함 |
| 통합 테스트(9차시) | 교사가 3~4차시 사이에 교사 앱에서 확인·승인 |

**조정한 4차시안** (교사 앱 「⏱️ 4차시 수업」에 타이머와 함께 들어 있음)

| 차시 | 주제 | 40분 구성 | 결과물 |
|---|---|---|---|
| 1 | 앱 월드 상상하기 · 주제 정하기 | 샘플 앱 월드 체험 5 · AI는 도우미 8 · 주제 탐색·선택 15 · 기획서 ① 10 · 백업 2 | 주제, 기획서 1~4번 |
| 2 | 게임 설계하기 | 짝 소개 3 · 규칙·캐릭터 14 · 기능·화면 칩 13 · 특별 기능·난이도 7 · 프롬프트 확인 3 | ★ 완성 기획서, 프롬프트 |
| 3 | AI와 함께 앱 만들기 | 사용 약속·시연 5 · 프롬프트→코드→실행 12 · 테스트·고쳐 줘 15 · 돌아보기·입점 신청 8 | 실행되는 앱, 입점 신청 |
| 4 | 우리 반 앱 월드 오픈! | 입장 안내 5 · 친구 부스 체험·좋아요 22 · 발표 10 · 돌아보기 3 | 앱 월드 오픈, 피드백 |

> 3차시가 가장 빠듯합니다. AI 응답이 늦거나 오류가 많은 학생을 위해 **난이도 「쉬움」**을 권하고, 마치지 못한 학생은 4차시 도입 5분에 마무리하도록 했습니다.

### 2-2. 교사 페이지를 이번 범위에 넣어야 함

4차시 안에 "제출 → 확인 → 입점"이 이어지려면 교사가 수업 사이에 20명의 결과를 한 화면에서 봐야 합니다. 그래서 기획서 11장의 "추후 구현" 항목 중 수업에 꼭 필요한 것만 먼저 만들었습니다.

- ✅ 학생별 제출·열람(기획서 + 앱 실행), 진행 상태, 피드백·수정 요청, 입점 승인, 부스 번호, 일괄 인쇄·백업
- ✅ 관리자(선생님) 계정 로그인 + 선생님이 만드는 학생 아이디(번호 + 4자리 비밀번호), 작업은 저장소에 자동 저장

### 2-3. 메타버스 입점 경로

기획서는 "완성 앱을 개별 URL로 게시 → 통합 메타버스 부스에 연결"입니다. 여기에는 두 가지 걸림돌이 있습니다.

1. **20명이 각자 웹에 게시**하려면 호스팅 계정·업로드 절차가 필요해 4차시 안에 어렵습니다.
2. AI 서비스의 **공유 링크는 대부분 다른 사이트 안에 넣어(iframe) 보여 주는 것을 막아** 두어서, 메타버스 부스 안에서 바로 실행되지 않고 새 창으로만 열리는 경우가 많습니다.
3. 외부 메타버스 플랫폼을 쓰면 부스마다 링크를 손으로 연결해야 하고, 승인·부스 번호와 자동으로 이어지지 않습니다.

→ **자체 앱 월드**를 만들었습니다. 학생은 AI가 준 **HTML 코드를 붙여 넣어 제출**하고, 교사가 승인하면 앱 월드에 부스가 자동으로 생기며 그 안에서 바로 실행됩니다. 공유 링크는 보조 수단(새 창 열기)으로 남겼습니다.

### 2-4. 저장과 취합

- 기획서 6-3의 지적처럼 브라우저 저장만으로는 교사가 모을 수 없습니다. → **우리 반 저장소**(선생님 구글 계정의 시트 + 드라이브, 무료) 또는 **제출 파일** 두 가지 길을 모두 열어 두었습니다.
- **공용 태블릿**을 여러 반이 돌려 쓰면 다음 학생이 앞 학생의 기획서를 이어 쓰거나 덮어쓸 수 있습니다. → 「새로 쓰기」 시 이전 기획서를 보관하고, 제출은 **기기가 아닌 기획서마다** 따로 저장되게 했습니다. 수업 끝에 「백업 내려받기」를 습관으로 만들어 주세요.

### 2-5. AI 도구 사용 조건 (수업 전 꼭 확인)

- 많은 생성형 AI 서비스는 **가입 가능 연령**이 정해져 있고(보호자 동의가 필요하거나 성인만 가능한 경우 포함), 서비스마다 다릅니다. 초등학생이 개인 계정으로 쓰기 어려울 수 있습니다.
- 선택지: ① 학교에서 학생용으로 허용한 교육용 계정의 AI 도구 ② 교사 계정으로 교사가 대신 입력(모둠별) ③ 교육청 안내 도구. 앱의 프롬프트는 특정 서비스에 묶이지 않게 "선생님이 알려 준 AI 도구"로 표현했습니다.
- 학생에게: 실명·학교·연락처를 프롬프트와 앱에 넣지 않기(개발자 이름은 **별명** 권장), AI 결과는 내가 확인하기.

### 2-6. 학생 앱 실행 안전

AI가 만든 코드는 예상치 못한 동작을 할 수 있습니다. 앱 월드·교사 앱·학생 앱 미리보기 모두 **격리 상자(sandbox)**로 실행해 이 사이트의 저장소나 다른 학생 데이터에 접근하지 못하게 했습니다. 격리 때문에 학생 앱의 기록 저장이 막혀 게임이 멈추는 일이 없도록 대체 저장소도 끼워 넣었습니다.

### 2-7. 문서 안 번호·용어 맞추기

- 5장(기획서 **15개** 항목), 9장(활동지 **11개** 활동), 부록 출력 양식(**13개** 칸)의 번호가 서로 다릅니다. 학생이 "몇 번 써요?"에서 헷갈립니다. → 앱·인쇄물은 **15번 체계**로 통일하고, 활동은 ①~⑤ 묶음으로 나눴습니다. 활동지도 15번 체계로 맞추는 것을 권합니다.
- 6-2의 "난이도·이미지 스타일"은 15개 항목에 자리가 없습니다. → 이미지 스타일은 11 디자인 계획, 난이도는 13 제작 계획 안에 넣었습니다.
- "통합 메타버스"의 플랫폼이 정해져 있지 않습니다. → 자체 앱 월드로 정리했습니다(2-3).

## 3. 결정이 필요한 것

| 항목 | 권장 | 비고 |
|---|---|---|
| AI 도구 | 학교 허용 교육용 계정 | 수업 전 연령·약관 확인 |
| 제출 방식 | 우리 반 저장소 (15분 설치) | 어려우면 제출 파일 방식 |
| 사이트 올리기 | GitHub Pages | 저장소 Settings → Pages |
| 기기 | 1인 1기기, https 주소 | 공용 기기면 백업 습관 |
| 이미지 생성 | 선택 과제 | 3차시 빨리 끝난 학생 |
